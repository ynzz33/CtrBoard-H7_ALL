## 0. 一句话

进测试模式后，主控每 **2 ms** 通过 VOFA 串口（JustFloat，921600 8N1）发一帧 **33 个 float**。
行分三类（看列 0）：`kind=1` 腿 / `kind=3` 轮 / `kind=5` 标记与心跳。
**拟合腿用 kind=1、拟合轮用 kind=3，kind=5 只做边界和健康检查。**

**VOFA+ 必须把通道数设成 33**，否则整列错位。

---

## 1. 33 列对照表（列含义以 `kind=1` 腿行为准）

| 列 | 名称 | 单位 | 来源 / 含义 |
| --- | --- | --- | --- |
| 0 | kind | - | 行类型：1=腿行、3=轮行、5=标记/心跳行 |
| 1 | seq | - | 全局递增序号（uint16，绕回）。**跳号 = 丢帧 → 该 run 判无效** |
| 2 | phase_or_event | - | 正数=当前段号；0=心跳；−1=run 开始、−2=run 结束、−3=中止 |
| 3 | t_cmd_hi | - | **输入时间戳**：四路腿力矩命令"成功送上 CAN 总线"的时刻，高位 |
| 4 | t_cmd_lo | - | 同上，低位 |
| 5 | tau_lf0 | Nm | **前左髋净力矩**（预压 + 激励，已限幅后真正下发的值） |
| 6 | tau_lf00 | Nm | 后左髋净力矩 |
| 7 | tau_rf0 | Nm | 前右髋净力矩 |
| 8 | tau_rf00 | Nm | 后右髋净力矩 |
| 9 | pos_lf0 | rad | 前左髋角（编码器解码值 + 零点偏置，**进解算用的就是它**） |
| 10 | pos_lf00 | rad | 后左髋角 |
| 11 | pos_rf0 | rad | 前右髋角 |
| 12 | pos_rf00 | rad | 后右髋角 |
| 13 | vel_lf0 | rad/s | 前左髋角速度 |
| 14 | vel_lf00 | rad/s | 后左髋角速度 |
| 15 | vel_rf0 | rad/s | 前右髋角速度 |
| 16 | vel_rf00 | rad/s | 后右髋角速度 |
| 17 | leg_length_L | m | **左腿长** = 髋轴到轮轴距离 \|OP\|（P 点 = 轮轴，不含轮径） |
| 18 | leg_pitch_L | rad | 左腿摆角（相对竖直方向，公式见 `sysid-delivery.md` §2） |
| 19 | leg_length_R | m | 右腿长 |
| 20 | leg_pitch_R | rad | 右腿摆角 |
| 21 | t_rx_hi | - | **轮反馈最近到达时刻**，高位 |
| 22 | t_rx_lo | - | 同上，低位 |
| 23 | t_leg_hi | - | **输出时间戳**：DM（腿）反馈最近到达时刻，高位 |
| 24 | t_leg_lo | - | 同上，低位 |
| 25 | d_len_L | m/s | **左腿长速度**（解算导数） |
| 26 | d_pitch_L | rad/s | 左腿摆角速度（解算导数） |
| 27 | d_len_R | m/s | 右腿长速度 |
| 28 | d_pitch_R | rad/s | 右腿摆角速度 |
| 29 | clamp_cnt | - | 本行被限幅的电机数。**>0 = 预压+激励顶到 20 Nm 被削平，该段数据无效** |
| 30 | preload_n | N | 预压沿腿力（正=伸腿，负=收腿）；轮行/标记行为 0 |
| 31 | whl_drop_cnt | - | 轮总线发送丢帧累计（正常恒 0） |
| 32 | leg_drop_cnt | - | 腿总线发送丢帧累计（正常恒 0） |

**输入输出配对（辨识用）**

```
输入 = 列 5~8（力矩，含预压）+ 列 3/4（上总线时刻）
输出 = 列 9~12（髋角）+ 列 17~20（腿长/摆角）+ 列 25~28（对应导数）+ 列 23/24（反馈到达时刻）
```

## 2. 同一列在不同行类型的含义差异

| 列 | `kind=1` 腿行 | `kind=3` 轮行 | `kind=5` 标记/心跳行 |
| --- | --- | --- | --- |
| 5 / 6 | 前左 / 后左髋力矩 Nm | **左轮 / 右轮命令 raw**（逻辑值 = round(I_A × 819.2)） | 见 §3 |
| 7 / 8 | 前右 / 后右髋力矩 Nm | 0 | 见 §3 |
| 23 / 24 | DM 反馈到达时刻 hi/lo | 左 / 右轮编码器原始值 | 左 / 右轮编码器原始值 |
| 25 / 26 | 腿长速度 / 腿摆角速度（左） | 左 / 右轮转速（电机侧 rpm） | 左 / 右轮转速 |
| 27 / 28 | 腿长速度 / 腿摆角速度（右） | 左 / 右轮**实际电流** raw | 左 / 右轮实际电流 |
| 29 / 30 | 削平计数 / 预压沿腿力 N | 0 / 0 | 0 / 0 |

> 轮行的列 23~28 在驱动解析时**已含反馈极性** `dji_sign.fb`，与列 5/6 的命令（逻辑值）**同域**，可直接做输入输出配对，不要再按轮次取反。

## 3. 标记行与心跳行（`kind=5`）

### 3.1 标记行（`phase_or_event = −1 / −2 / −3`）

| 列 | 含义 |
| --- | --- |
| 5 | run_index（本次 run 序号，从 0 起） |
| 6 | test_id（用例编号） |
| 7 | 该 run 的总段数 |
| 8 | 0 |
| 其余 | 照常填当时的状态值（腿长、髋角等） |

**用 −1 和 −2/−3 作为 run 边界切分数据。**

### 3.2 心跳行（`phase_or_event = 0`，每 250 ms 一条，停机时也发）

| 列 | 含义 |
| --- | --- |
| 5 | 当前 run_index |
| 6 | 当前 test_id |
| 7 | 当前段号 |
| 8 | **状态码**：0=正常、1=总输出被关、2=有 DM 离线、3=腿解算无效、4=激励表为空、5=姿态表已跑完设定遍数 |
| 9 | 重入重置累计（一直涨 = 拨杆信号在抖、模式被反复重进） |
| 10 | 环形缓冲丢帧累计（涨 = 采样快于发送，数据有缺口） |
| 11 | 串口忙跳过累计（一直涨 = 发送被 UART 顶住） |
| 12 | 心跳计数（在涨 = 数据流活着） |
| 13 | **串口卡死自恢复次数**（>0 = 出现过 HAL 发送状态卡死，已被看门狗救回） |

> 心跳行只用来判断"板子在干什么"；**它不进任何 CSV**。

### 3.3 事件码

| 值 | 含义 |
| --- | --- |
| −1 | run 开始 |
| −2 | run 结束 |
| −3 | 中止（总输出关 / DM 离线 / 解算无效），之后只发零力矩 |
| 0 | 心跳 |
| ≥1 | 当前段号（同一 run 内的激励阶段） |

## 4. 时间戳怎么还原

帧里所有 64 位纳秒时间戳都拆成两个 float32（`hi = ns >> 20`、`lo = ns & 0xFFFFF`）：

```
ns = 列_hi × 1048576 + 列_lo
```

三对时间戳：

| 含义 | hi / lo 列 |
| --- | --- |
| 腿力矩命令**上总线**时刻（输入） | 3 / 4 |
| 轮反馈**到达**时刻（输出） | 21 / 22 |
| DM 反馈**到达**时刻（输出） | 23 / 24 |

**⚠️ 单独看 hi 列会像是"5000 这种数"——那是正常的**（开机 5.2 秒时正好 ≈5000，每 1.05 ms 涨 1）；单独看 lo 列会来回跳（0~1048575），也是正常的。必须两列一起还原。

## 7. 常见"看起来不对"的说明（先看这里再怀疑固件）

| 现象 | 真相 |
| --- | --- |
| 列 3/4 是 5000 和大数 | **时间戳拆分**，正常（见 §4） |
| 列 21/22 同上 | 轮的到达时刻，同样拆分 |
| 列 29/31/32 一直是 0 | 就是应该为 0 |
| 列 5~8 大部分时间是同一个常数 | 那是**预压**；激励是稀疏的（阶跃用例每 5.5 秒只有一个 0.5 秒脉冲） |
| 列 23/24 在轮行不是时间戳 | 轮行这两列是轮编码器，见 §2 |
| 心跳行（每 250 ms 一条）列 5~12 含义不同 | 见 §3.2，这不是数据行 |
| 腿长显示 0.40+ 且几乎不变 | 腿被气弹簧顶在"接近伸直"的姿态，**该姿态下沿腿的力压不动腿**，需要机械把腿放到行程中段 |
